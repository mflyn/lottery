## 本次修正

26014 期起的常规固定奖如下，单位为元：

| 奖级 | 开奖前奖池低于 8 亿元 | 开奖前奖池达到 8 亿元 |
| --- | ---: | ---: |
| 三等奖 | 5000 | 6666 |
| 四等奖 | 300 | 380 |
| 五等奖 | 150 | 200 |
| 六等奖 | 15 | 18 |
| 七等奖 | 5 | 7 |

三等奖合并 5+0、4+2；五等奖合并 4+0、3+2；七等奖合并原九等奖条件。
追加投注只参与一、二等奖的浮动奖金分配，追加部分为基本单注奖金的 80%，按元取整；固定奖不增加追加奖金。

## 程序行为及边界

- `draw_issue` 可使用五位 YYNNN 或七位 20YYNNN。省略时按当前七奖级规则处理。
- 19019—26013 期使用九奖级；更早的期号明确报不支持，不套用较新的规则。
- 一、二等奖不能仅靠命中号码和奖池推算。`floating_prizes` 接收官方公告中的基本单注奖金；没有时返回 `(奖级, None)`。
- 历史数据的 `prize_pool` 是该期开奖后的余额。核对某一期时，只使用紧邻上一期的余额作为其开奖前奖池，不能使用该期自身的余额。
- 历史加载会把缺失奖池补为 0。因此自动上下文中的零余额保守视为未知；缺少上一期、跨年首期尚无完整上下文、号码被手动修改等情况也不猜奖金。
- 核奖界面只汇总已知金额。含未知金额时显示“已知奖金小计”和待核实提示。
- 独立 API 的 `prize_pool=0` 默认值保留为低奖池条件试算；查询真实开奖时应传入已核实奖池或 `None`。
- 这里实现常规奖级表。特别奖、风险控制下的调整及最终兑付以当期官方公告为准；不自行根据不完整销售/中奖信息推算这些金额。
